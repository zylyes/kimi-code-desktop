# Librarian 记忆（kimi-code-desktop）

## 官方事实（来源：MoonshotAI/kimi-code 源码 + code.kimi.com + ACP 规范；2026-08-02 实弹验证与二轮调研、2026-08-04 Node/Windows TOCTOU 研究）

- 版本真相源是 CDN `https://code.kimi.com/kimi-code`（302→cdn.kimi.com），非 npm/GitHub Releases。Endpoint 链：`/latest`（纯文本 semver，install.ps1 默认取版本、CLI fallback）、`/latest.json`（灰度清单 `{schemaVersion,version,publishedAt,rollout:[{percent,delaySeconds}]}`，schema 非 strict、字段可新增）、`/binaries/<v>/manifest.json`（`{version,tag,platforms:{win32-x64:{filename,checksum}}}`，sha256 64hex）、`/binaries/<v>/<filename>`（win32 为 `kimi-code-win32-<arch>.exe`）。CLI 超时 3s，`/latest.json` 失败静默回退 `/latest`，两者都失败才报错。版本比较官方用 `semver.gt`（本地 compareSemver 只比 3 段数字、不处理 pre-release，有偏差）。
- install.ps1：`KIMI_VERSION` 固定版本，否则 GET `/latest` → manifest → 下载 → sha256 校验 → 复制到 `<KIMI_INSTALL_DIR 或 ~/.kimi-code>\bin\kimi.exe`（旧 exe 先改 .bak），覆盖即升级。Windows native 无法自动升级（`canAutoInstall('native','win32')===false`），只提示手动 `irm https://code.kimi.com/kimi-code/install.ps1 | iex`。
- `~/.kimi-code/updates/latest.json`：CLI 本地缓存，非主动源。strict schema `{source:'cdn',checkedAt:ISO|null,latest:semver|null,manifest:{version,publishedAt,rollout[]}|null}`；仅 CLI 启动 preflight 写；网络失败不写（保留旧值）；读失败返回全 null。
- 源码仓库：MoonshotAI/kimi-code（TS, MIT, monorepo：apps/kimi-code=CLI/TUI、packages/acp-adapter=ACP 层、agent-core-v2、node-sdk、oauth），勿与 Python 版 MoonshotAI/kimi-cli 混淆；最新 @moonshot-ai/kimi-code@0.31.1（2026-07-31）；文档源 = 仓库 docs/（发布到 moonshotai.github.io/kimi-code 与 kimi.com/code/docs）。
- 数据目录（data-locations.md）：`~/.kimi-code/`（KIMI_CODE_HOME 可迁移）；会话 `sessions/<wdKey>/<sessionId>/`（wdKey=`wd_<slug>_<sha256前12>`）；wire.jsonl 在 `agents/main/`（主）与 `agents/agent-N/`（子代理）；`state.json`（title/lastPrompt/forkedFrom）；`tasks/`、`cron/`、`session_index.jsonl`；usage.record 是 wire.jsonl 里的记录类型（文档未列独立文件）。
- wire 记录：`usage.record` `{type,model,usage:{inputOther,output,inputCacheRead,inputCacheCreation},usageScope:'session'|'turn',time}`；`turn.step.completed`（含 usage）；`context_size.measured`；`config.update`；v1 `agent.status.updated`（合并 usage+contextTokens+maxContextTokens+model；v2 拆分独立 Op）。
- TUI /usage（commands/info.ts）：session.getUsage()（SessionUsage{byModel,currentTurn,total}）+ contextTokens/maxContextTokens（live agent.status.updated 事件或回放 resume state）+ getManagedUsage（仅 provider='managed:kimi-code' OAuth）；/status：session.getStatus()（SessionStatus 含 model/thinkingEffort/permission/planMode/contextTokens 等）+ appState。
- 平台额度接口：`GET {KIMI_CODE_BASE_URL 默认 https://api.kimi.com/coding/v1}/usages`，`Authorization: Bearer <OAuth accessToken>`，超时 8s，401/404 有专用提示。响应 `{usage:{used,limit,resetTime},limits:[{window:{duration,timeUnit},detail}],boosterWallet}`，数字为十进制字符串；summary=周配额、extraUsage=booster 钱包（fixed-point 1e6）；API key 等其他 provider 无此接口。
- ACP（kimi acp，@agentclientprotocol/sdk@0.23.0）：agent-side 稳定 10/12（initialize/authenticate/session:new/load/resume/prompt/cancel/list/set_mode/set_config_option），reverse-RPC 4/9（session/update、session/request_permission、fs/read、fs/write）；authMethods 仅 terminal-auth（id 'login'）；session/update 变体：agent_message_chunk/agent_thought_chunk/tool_call/tool_call_update/plan/config_option_update/available_commands_update；**kimi 未实现 ACP 的 usage_update**（规范 MAY，used/size/cost）。
- ACP 内置 slash（builtin-commands.ts）：compact/status/usage/mcp/tasks/help；ACP 下 `/usage`=formatUsageReport(getUsage,getStatus)（**无平台配额**，TUI 版才有）；未知命令报 "Unknown ACP command"。
- Task/TaskOutput/TaskStop/CronCreate/CronList/CronDelete/Agent 均为 **Agent 内置工具**（tool registry，profiles.ts 默认含），非 ACP RPC；对 ACP 客户端仅以 tool_call 通知呈现（toolCallId=`${turnId}:${rawId}`）；rpcService.ts 的 getTaskOutput/getTasks 是内部 RPC（kap-server），非 ACP。
- **ACP 无子代理身份**：SessionUpdate 无 parent/child 字段（_meta 是保留扩展点）；kimi adapter 用 isFromMainAgent（agentId===undefined||'main'）过滤，子代理事件不推送；内部 metadata：registerAgent 记 {type:'main'|'sub',parentAgentId,forkedFrom,labels}，子代理再派生时 labels 带 parentAgentId+swarmItem；hook 命令 SubagentStart/SubagentStop。
- 状态条计数（footer.ts + session-event-handler.ts）：`[N task running]`=当前**非终态**（跳过 completed/failed/timed_out/killed/lost）的 bash 后台任务数；`[N agent running]`=同类后台子代理数；两徽章独立。
- Node/Windows TOCTOU（2026-08-04）：**O_NOFOLLOW 在 Windows 不可用**（libuv `UV_FS_O_NOFOLLOW 0`，win32 上 `fs.constants.O_NOFOLLOW` undefined，fs.md 仅列 O_APPEND/O_CREAT/O_EXCL/O_RDONLY/O_RDWR/O_TRUNC/O_WRONLY/UV_FS_O_FILEMAP）；**fs.realpath 全家不支持 fd**（path 仅 string/Buffer/URL，FileHandle 无 realpath）。
- lstat 与 readdir 都能识别 junction（libuv 用 FILE_FLAG_OPEN_REPARSE_POINT 不跟随打开，任何 reparse point 置 S_IFLNK → isSymbolicLink() 为 true）；**Windows 上 st_ino 有效**（NTFS FileId，需 bigint:true 拿全 64 位）→ lstat 与 open 后 fstat 的 (st_dev,st_ino) 对比可做"打开后验证"，连 rename 替换（非 symlink）也能发现。
- **Node 纯 JS 层无原子防 reparse 跟随手段**（无 O_NOFOLLOW/openat/FILE_FLAG_DISALLOW_PATH_REDIRECTS 暴露，需 native 模块）；现实模式 = lstat 检查 + open 后 fstat 对比（可验证关闭的 TOCTOU）。
